Key Architectural Takeaways

ETTA Strengths (Single-Shot Streaming Reflex):
  • Interactive Speed (5.7x Faster): Direct streaming via HTTP/2 persistent transport completes problems in 15–35s.
  • Extreme Token Efficiency (9.8x Fewer Tokens): Zero transcript re-transmission. Incurs no multi-turn quadratic context overhead.
  • Direct Production Purity: Solves 90%+ of brutal edge cases cleanly on the very first turn.
AGY Strengths (Iterative Verification Loop):
  • Self-Healing via Unit Tests: Autonomously creates internal test scripts and runs linter commands before finalizing code.
  • Higher Peak Accuracy (95.8%): Caught subtle heap-rebalancing edge cases on duplicate sliding windows.
  • Trade-off: Takes ~8 minutes and consumes 404,000+ tokens due to re-sending full transcript histories.

Algorithmic & Code Comparison

ETTA Architectural Highlights (136 LOC | 34.04s)

• Dynamic Admissibility Scaling: ETTA computed min_weight of the passable grid and scaled the Octile/Manhattan distance by min_weight, mathematically guaranteeing that the heuristic never overestimates when 0-weight cells exist.
• Pre-allocated 2D Matrices: Avoided hash map collisions by pre-allocating contiguous 2D lists for g_score, closed, and parent.
• Local Function Inlining: Cached heapq.heappush and heapq.heappop into local references for C-level call dispatch.

AGY Architectural Highlights (160 LOC | 126.80s)

• Dynamic Hash Table Lookup: Used dict[tuple[int, int], float] for g_score and came_from. Clean and readable, but incurs hash table probing overhead.
• Iterative Self-Verification: Generated an automated unit test script, verified tie-breaking, and verified zero-cost handling during its multi-turn execution.
• Standard Heuristics: Assumed minimum terrain cost is ≥ 1.0 for standard Octile distance calculation.

Deep Mathematical Audit: Case 10 Discovery

Both AI Models Proved Mathematically Superior to the Initial Test Harness:
In Case 10 ("bbaaaaaaaaaaaaaaacccc"), the initial evaluator expected 8. However, both ETTA and AGY independently produced 6.
Verification Proof: Length is 21 → 1 deletion is mandatory to reach max length 20. Deleting 1 'a' from the 15-long repeat leaves 14 'a's (requires 14 // 3 = 4 replacements) and 4 'c's (requires 4 // 3 = 1 replacement), totaling 5 replacements. The 5 replacements can simultaneously introduce the missing uppercase and digit characters. Therefore: 1 deletion + 5 replacements = 6 total operations. Both models solved the true mathematical optimum.

ETTA Performance (71 LOC | 19.57s)

• Direct Single-Pass Generation: Streamed concise, functional greedy logic in under 20 seconds.
• Modulo Priority Arrays: Grouped repeats into three buckets k % 3 == 0, k % 3 == 1, k % 3 == 2 and greedily drained deletions.
• Zero Wasted Compute: 11,740 total tokens.

AGY Performance (104 LOC | 173.06s)

• Verbose Casework: Separated length categories ($N < 6$, $6 \le N \le 20$, $N > 20$) into explicit helper functions.
• Multi-turn Verification: Executed internal unit tests before writing the final solver file.
• Compute Cost: Consumed ~112,485 tokens across 173 seconds.

Algorithmic & Performance Comparison

Result: Flawless Execution on Both Engines, But ETTA Finished 9.0x Faster:
Both models scored a perfect 12/12, correctly resolving the sweep-line event ordering (start events with negative heights so taller buildings are processed before shorter ones at the same X coordinate; end events with positive heights; start events processed before end events at identical junctions).
Latency Differential: ETTA completed the implementation in 15.32 seconds, whereas AGY took 137.31 seconds.

ETTA Sweep-Line Design (65 LOC | 15.32s)

• Clean Event Tuple Tuple Sorting: Used (x, -h, R) for starts and (x, 0, 0) with lazy heap eviction.
• Lazy Heap Popping: Stored (-h, right) in max-heap; popped stale buildings whose right ≤ curr_x.
• Deduplication Invariant: Appended to output only when max_height != prev_height.

AGY Sweep-Line Design (90 LOC | 137.31s)

• Multi-Key Event Sorting: Explicitly split start and end events with typed boundary tags.
• Comprehensive Validation: Tested all 32-bit boundary conditions before writing the final module.
• Execution Overhead: Required 89,253 tokens across its sandbox validation turns.
